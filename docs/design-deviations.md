# Design deviations

The desktop exports in `0. Mockups/HTML/DESKTOP/` are the authority for composition: what sits where, how big it is, what rule separates it, and what the eye sees first. Where they are silent — states, Greek, mobile, forms, errors, staging — the build makes the closest-neighbour choice from existing tokens and records it here. Accessibility wins over the mockup when the two conflict.

Each departure needs a one-line reason and a status so the committee can review the list rather than discovering changes in the browser.

| Departure | Reason | Status |
|---|---|---|
| Language switcher in the nav row | Bilingual launch; the mockup predates the decision. It is sized and spaced as a nav item and kept outside the primary `<nav>` landmark. | In this build (Task 3) |
| Hover, focus and active states | Absent from the mockup. Designed once from existing tokens: 1 px underline on hover/active, a 2 px black focus outline offset 3 px, and reverse video on pill hover — no transitions longer than 120 ms. | In this build (Task 3) |
| `#b3b3b3` text replaced with `#6e6e6e` where it must be read | The mockup grey is about 2.1:1 on white and fails WCAG AA at body size; `#6e6e6e` is about 5:1. `#b3b3b3` stays decorative only. | In this build (tokens from Task 1, applied as text lands) |
| Greek wrapping in the nav and tier names | Greek strings run longer. Type size and spacing hold and lines wrap rather than shrinking below the ramp. | In this build for the nav (Task 3); tier names with Task 8 |
| Mobile layouts | The mobile exports reuse desktop absolute coordinates and cannot be used. Mobile is composed from the desktop grid and the same 8 px spacing steps, with a smaller nav and body ramp. | Layout frame in this build (Task 3); full pass in Task 17 |
| Form validation and success states | Not in the mockup. Designed from the same 1 px rules, type ramp and plain-language error copy, with errors adjacent to their fields. | Pending Task 12 |
| 404 and error pages | Not in the mockup. Composed from the same type ramp, rules and a single route back to the home page. | Pending Task 15 |
| Footer text inset at the 60 px page frame instead of the mockup's 9 px | Header, main and footer share one frame so their left edges align at every width; the mockup's 9 px inset would step outside the grid. | In this build (Task 3) |
| Staging badge in the footer | A staging-only marker, paired with `noindex, nofollow`, so nobody mistakes the review site for the live one. Removed at cutover. | In this build (Task 3) |
| Mark optimised from 1514 × 2085 / 12.6 MB to 800 px on the long edge | The source is displayed at roughly 158 × 192 px; keeping the original would ship megabytes for no visible gain. The 800 px long edge leaves room for high-density displays. | In this build (Task 1) |
| Home h1 is the visible hero lockup | The mockup renders the wordmark once, as the hero; that copy is the h1, and the header brand is suppressed on home so it is not duplicated. The two-span split keeps the accessible name reading "CYPRUS PRINTMAKERS ASSOCIATION" while the mark sits between the words on desktop and above them on mobile. | In this build (home hero) |
| About history prose keeps the 36 px export size, the intro does not | The export sets the whole long text at 36 px. The short fixture intro keeps the 24 px body ramp and a 40 em measure so the page has one clear hierarchy; the history — the export's dominant block — stays at 36 px per the mockup. | Superseded 2026-11-04: the fluid scale sets history at body size |
| About committee and partners sections | Not in the export, which ends after the history text. Composed from the shared vocabulary: 1 px rules between sections, 32 px section headings, 24 px names, 20 px roles. | In this build (Task 6) |
| Home entry sequence | The static exports have no motion. Reconstructed from the public Figma prototype (captured 2026-11-02): a floating logo cover that waits for a click, then the wordmark slide-in and a measured hand-off to the hero lockup. Runs on every full home load; never with reduced motion, no JS, or a client-side arrival at home. | In this build (motion pass, updated by the home hero) |
| Page dissolve between internal pages | The prototype dissolves (~300 ms). Implemented with Astro's client router and native view transitions; no layout or content changes. | In this build (motion pass) |
| Intro clone uses the hero's available width | The clone wraps exactly like the home hero lockup: `intro.js` measures `[data-hero-lockup]` and constrains the stage to that rendered width before animating, so uniform scaling cannot distort wrapping. At 320 px the Greek clone and hero rects match within 1 px at hand-off. | In this build (home hero) |
| Intro failure fallback | The cover shows the server-rendered mark immediately, and the 4 s guard clears the cover if `intro.js` never arrives. A blocked script leaves a readable page, not a blank cover. | In this build (home hero) |
| Motion respects `prefers-reduced-motion` | The entry is skipped and view-transition pseudo-elements are explicitly disabled; the page renders its final state immediately. | In this build (motion pass) |
| Filters and forms re-initialise on `astro:page-load` | Client-side navigation replaces the DOM without re-running scripts keyed by `src`; each script now binds once to `astro:page-load`. No visual change. | In this build (motion pass) |
| Home cover waits for a click | The static exports have no entry state; the prototype shows a floating logo mark that the visitor clicks to enter. The cover shows only the mark, centred, until then, and it appears on every full home load rather than once per session. Reduced motion, no JS and client-side arrivals skip straight to the hero. | In this build (home hero) |
| Nav, `CURRENT` and the page are hidden until the hand-off | The prototype shows the nav and `CURRENT` line before the entry completes. The page stays `visibility: hidden` while the cover waits or moves, so the first screen is the mark alone and the skip link, nav and footer cannot be reached behind it; they appear together when the cover hands off. Escape or a click during the sequence reveals them early. | In this build (home hero) |
| Home hero paragraph is transient | The optional paragraph is editorial copy with no place in the static exports' settled home. It fades in after the click, holds long enough to read (about 3.5 s), then fades out before the hand-off to the hero lockup, so the settled home matches the export. | In this build (home hero) |
| Home footer stays in normal flow | The home fills the viewport with nav, hero and `CURRENT`; the footer follows in normal flow so the page can grow on short or zoomed viewports instead of overlapping the hero. | In this build (home hero, final fixes) |
| Desktop hero paragraph sits under the wordmark | The prototype places the transient paragraph to the right of the lockup; the build anchors it below/right of the tail wordmark so it cannot overlap that text, and hides it before the hand-off. | In this build (home hero, final fixes) |
| Header brand is hidden on home | The mockup's home shows one wordmark, the hero lockup. The header renders no brand on home so the entry and the settled page do not show a second copy; every other page keeps the header brand as a link home. | In this build (home hero) |

| Fluid type scale instead of the export's 24/32/36 px | The export has one fixed size per role and no mobile ramp. Body is 17 px on phones and 20 px on desktop, the four roles are fluid, and prose is capped at 65 characters — the export's 24 px body at full width is hard to read on both a phone and a wide screen. | In this build (2026-11-04) |
| Membership page is the application form, not the tier table | The tier mockup reuses phytorio prices that the committee has not confirmed. The page shows the back link, the black intro, name/email/mobile/motivation/CV, consent and submit; `/support` keeps the sponsorship tiers. | In this build (2026-11-04) |
| Membership asks for a CV and a motivation, and keeps consent | The request-form mockup marks the motivation and CV as required. Email is also required so the committee can reply, and the privacy consent stays for GDPR. Labels are black rather than grey for contrast. | In this build (2026-11-04) |
| CV is uploaded, not linked | The form posts multipart to `/api/membership`, which attaches the CV to the committee email through Resend; limits stay PDF/DOC/DOCX up to 4 MB. | In this build (2026-11-04) |
